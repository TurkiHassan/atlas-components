## كيف تقرر

طبّق `SELECTION-CRITERIA.md` قبل التثبيت. افحص المصدر الرسمي ورخصة الإصدار المنشور، التوافق، الصيانة، الإتاحة، العربية، الجوال، حجم التكامل وتكرار الوظيفة. النجوم والانتشار والجمال وحدها لا تكفي. لا تُضف مصدرًا إذا كان يؤدي دورًا مغطى دون فائدة واضحة.

يفضل تقرير مختصر عن أقوى المرشحين مع أسباب القبول أوالاستبعاد على تثبيت عشرات الحزم. لا يلزم أن تضيف كل دورة مكوّنًا جديدًا.

## التحديث المصرح به

1. راجع سجل البحث وطلبات السحب المفتوحة لتجنب التكرار، ثم اجلب أحدث `origin/main` دون المساس بالتعديلات المحلية.
2. استخدم فرعًا وworktree مستقلين عند وجود تغيير مفيد.
3. طبّق التحديث المتوافق أوأضف المكوّن الجاهز مع مثال فعلي ومصدره. احتفظ بعزل HeroUI، وسلّم الخطوط المعتمد، والوظائف الحالية.
4. حدّث lockfile وprovenance والتراخيص والفهرس والتوثيق المتأثر. ارفع رقم الإصدار عند تغيير الحزمة القابلة للتوزيع.
5. شغّل `npm run check` و`npm run provenance` و`npm run test:package`، وافحص المظهر والجوال والاتجاهين عند تأثر الواجهة. تحقق من الحالات التي تعالجها الإضافة، لا من مجرد نجاح الاستيراد.
6. ادفع الفرع وافتح Draft Pull Request يشرح المشكلة والسلوك الناتج والأدلة والاختبارات والقيود. إن وُجد PR مناسب فحدّثه بدل فتح نسخة أخرى. أرفق PR بالمحادثة عبر أداة الإرفاق المتاحة.
7. أخبر المستخدم عند وجود تغيير مفيد أوفشل حقيقي أوحاجة إلى قرار، وأدرج رابط PR. الدمج في main والنشر إلى npm أوتغيير الأساس تتطلب تعليمات صريحة؛ لا تنفذها تلقائيًا.

إذا لم تجتز الإضافة المعايير أوالاختبارات، وثّق السبب وأبقها مرشحًا. لا تعطل الاختبارات ولا تخفِ أعطال المصدر. عند غياب مستجد مهم لا تنشئ PR فارغًا ولا إشعارًا متكررًا.

## سجل كل دورة

اكتب `research/weekly/YYYY-MM-DD.md` عند وجود بحث جوهري، ويشمل:

- تاريخ البحث وروابط المصادر وتواريخ الإصدارات.
- المرشحين، الحاجة، التقييم والقرار.
- الشكاوى ذات الصلة وحالتها والإصدار الذي تتعلق به.
- التغيير الفعلي ونتائج التحقق والقيود ورابط PR إن وُجد.
