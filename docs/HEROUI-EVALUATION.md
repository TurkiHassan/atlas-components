# تقييم HeroUI لمكتبة أطلس

تاريخ المراجعة: 22 أكتوبر 2026. المستودع: [heroui-inc/heroui](https://github.com/heroui-inc/heroui). هذه وثيقة مرحلة مراجعة المصدر والتوثيق وبيانات الحزم وعينة المشكلات. أُنجزت لاحقًا المقارنة المحلية الموصى بها؛ نتائجها المنفصلة في [المقارنة العملية](COMPARISON-RESULTS.md). العبارات التالية عن عدم الاختبار تصف مرحلة المراجعة الأولية فقط.

## الحكم

HeroUI v3 مرشح قوي للواجهات الحديثة ذات الطابع البصري المصقول، خصوصًا مع React 19 وTailwind 4. لا يوجد سبب لاستبعاده بسبب شهرته أوأصل NextUI؛ أساسه الحالي React Aria، وتوفره كحزم جاهزة يناسب طلب عدم إعادة بناء المكونات. ملاءمته للمشروع الحالي تعتمد على أولوية الجمال مقابل اكتمال المجموعة وسهولة دمجها.

الاختيار الحالي لـMantine يبقى منطقيًا لمجموعة واسعة ومتجانسة تشمل الرسوم والمحرر والملفات. HeroUI يستحق مقارنة بصرية منفصلة قبل استبدال الأساس، لا تركيب نظامي تصميم كاملين تلقائيًا.

## الإصدار والنطاق

- أحدث إصدار مستقر تحققت منه GitHub وnpm هو **3.2.6**، نشر في 17 سبتمبر 2026. تغييرات الفرع الافتراضي بعده ليست بالضرورة موجودة في الحزمة المنشورة. [الإصدار](https://github.com/heroui-inc/heroui/releases/tag/v3.2.6)، [سجل التغييرات](https://heroui.com/en/docs/react/releases/v3-2-6).
- المتطلبات الرسمية: React 19+ وTailwind CSS v4. إرشادات v2 التي تعتمد HeroUIProvider وFramer Motion ليست إعداد v3. [البدء](https://heroui.com/en/docs/react/getting-started/quick-start)، [الترحيل](https://heroui.com/en/docs/react/migration).
- مصدر المراجعة التقنية مثبت عند commit `d814c204a92464ca02eb229c384a4a982d1ab398` على v3؛ تفاصيل الملفات والاختبارات في [مذكرة المصدر](../research/HEROUI-REPO-NOTES.md).

## نقاط القوة المؤثرة

### أساس الإتاحة والتخصيص

يعتمد v3 على React Aria Components، مع أنماط تركيب تتيح تغيير أجزاء المكونات. يفصل `@heroui/styles` عن `@heroui/react`، ويتيح CSS variables وBEM وTailwind. هذه صفات مناسبة لمكتبة تستورد الجاهز ثم تضبط مظهره دون إعادة تنفيذ سلوك Dialog أوSelect. لا تعفي من اختبار التباين والتسميات والتدفقات في التطبيق. [التصميم](https://heroui.com/en/docs/react/getting-started/design-principles)، [المقدمة](https://heroui.com/en/docs/react/getting-started).

### ميزة مهمة للسعودية: تعدد التقاويم

يوثق DatePicker استخدام I18nProvider وامتدادات locale لتغيير التقويم. يوفر محرك `@internationalized/date` تنفيذ `IslamicUmalquraCalendar` بالمعرّف `islamic-umalqura`. لذلك يوجد مسار موثق لعرض أم القرى دون بناء تقويم محلي. هذا استنتاج من توافق المكون الموثق مع المحرك، ولم يُختبر هنا كتدفق سعودي كامل. يجب التحقق من عرض الأشهر والأرقام ونطاق التاريخ والتحويل وقيم onChange؛ تغيير تقويم العرض لا يعني أن قيمة التخزين تحولت إلى هجري. [HeroUI DatePicker](https://heroui.com/en/docs/react/components/date-picker)، [تنفيذ التقاويم في Adobe](https://react-aria.adobe.com/internationalized/date/Calendar).

### الجدول أوسع من مجرد عرض ثابت

يدعم التوثيق الفرز والاختيار وتغيير عرض الأعمدة والتحميل عند التمرير، والتركيب مع Virtualizer أوTanStack Table. لا يصح وصفه بأنه جدول بسيط فقط. في المقابل، تظل إدارة مصدر البيانات وحالات الفرز والتصفية وتركيب الأجزاء مسؤولية التطبيق. [Table](https://heroui.com/en/docs/react/components/table).

### صيانة تعالج ملاحظات حقيقية

الإصدار 3.2.6 وثق تحسين ثبات السياق في 43 مكونًا وتصحيحات التركيز وتبعيات التاريخ. هذا دليل علاج واضح، وليس قياسًا بأن HeroUI أسرع من Mantine. شكاوى RTL القديمة عولجت جزئيًا في 3.1 ثم إصدارات لاحقة؛ لا تُعرض كأنها عيوب مفتوحة كلها اليوم. [3.2.6](https://heroui.com/en/docs/react/releases/v3-2-6)، [3.1.0](https://heroui.com/en/docs/react/releases/v3-1-0)، [القضية المغلقة 6445](https://github.com/heroui-inc/heroui/issues/6445).

## ملاحظات محددة قبل الاعتماد

1. **التوطين ليس كاملًا تلقائيًا:** القضية المفتوحة [6945](https://github.com/heroui-inc/heroui/issues/6945) تخص 3.2.6؛ CloseButton يحمل تسمية إنجليزية افتراضية. المصدر يؤكد الافتراضي، والبلاغ يوضح أثره في زر إغلاق Toast. لا يكفي ضبط dir أوlocale وافتراض أن كل التسميات عربية.
2. **تفاعل اللوحة على الجوال:** القضية المفتوحة [6967](https://github.com/heroui-inc/heroui/issues/6967) تبلغ عن تعليق حالة سحب Drawer بعد pointercancel على Android. يوجد نقص مقابل في المعالجات المفحوصة، لكننا لم نعد إنتاج البلاغ على جهاز هنا.
3. **الترخيص يحتاج اتساقًا في السجل:** root LICENSE ونص LICENSE داخل tarballs للإصدار 3.2.6 هما Apache2.0؛ package.json يعلن MIT. هذا تعارض metadata، وليس دليلًا على ترخيص مزدوج. ينبغي حفظ النص المرفق وتسجيل الاختلاف عند إعادة توزيع مكتبة. [النص الجذري](https://github.com/heroui-inc/heroui/blob/d814c204a92464ca02eb229c384a4a982d1ab398/LICENSE)، [بيانات حزمة React](https://registry.npmjs.org/@heroui%2Freact/3.2.6)، [بيانات Styles](https://registry.npmjs.org/@heroui%2Fstyles/3.2.6).
4. **تركيب بعض المكونات أطول:** DatePicker مثال صريح على تجميع أجزاء الحقل والتقويم والمحفز والنافذة. هذا يمنح تحكمًا أكبر لكنه يحتاج شيفرة إعداد أكثر من مكوّن مغلف عالي المستوى. الأجزاء نفسها جاهزة؛ لا يعني ذلك إعادة بناء المكوّن.
5. **لا نفترض أن أدوات الذكاء الاصطناعي ميزة حصرية:** HeroUI لديه MCP وملفات توثيق مهيأة، لكن Mantine أيضًا يعلن أدوات مشابهة. لا يعتمد القرار على المقارنة التسويقية في README.
6. **الفهرس الحالي لا يغطي كل امتدادات مجموعتنا:** لم يظهر ضمن قائمة مكونات React الحالية ما يعوض منظومة الرسوم والمحرر الغني وDropzone المثبتة في أطلس؛ يلزم تركيب مصادر متخصصة إذا استُبدل الأساس. هذا وصف للفهرس الحالي، لا ادعاء استحالة التكامل. [فهرس المكونات](https://heroui.com/en/docs/react/components).
7. **مسار الاستيراد يحتاج انتباهًا:** يشير README إلى حزم منفصلة مثل `@heroui/button`، لكن latest لهذه الحزمة وقت الفحص هو 2.2.32 مع اعتماديات v2. أما v3 فيوفر مسارات مثل `@heroui/react/button` داخل حزمة React نفسها. لا تخلط التثبيت القديم مع وثائق v3. [بيانات Button](https://registry.npmjs.org/@heroui%2Fbutton/latest)، [صادرات React 3.2.6](https://registry.npmjs.org/@heroui%2Freact/3.2.6).

## المقارنة العملية لأطلس

| الحاجة | HeroUI | الوضع الحالي في أطلس |
|---|---|---|
| واجهة حديثة قابلة للتخصيص عبر Tailwind | مرشح ممتاز | Mantine مضبوط بسمة عربية |
| إتاحة وتدويل | أساس React Aria قوي؛ يلزم تحقق من التسميات | تكامل Mantine المفحوص حاليًا، مع حدود الاختبار الموثقة |
| تقويم أم القرى | مسار موثق عبر React Aria ومحرك التواريخ | المثال الحالي ميلادي عربي؛ لا إضافة هجري |
| الرسوم والمحرر والملفات | تتطلب مكتبات تكميلية | امتدادات متوافقة مثبتة ومجرّبة |
| إدخاله الآن | يحتاج إضافة Tailwind وتوحيد الأنماط وإعادة اختبار التدفقات | المعرض والحزمة الحالية اجتازا اختبارات التكامل |

**التوصية:** إبقاء HeroUI مرشحًا جادًا كأساس بديل لمشروع جديد أوواجهة تعطي أولوية للتخصيص البصري والهجري. قبل تحويل أطلس، أنشئ مقارنة منفصلة على المحتوى نفسه للنموذج والحوار والجدول والتاريخ، وافحص العربية واللمس والإتاحة وحجم البناء. لا يوجد دليل حالي من هذه المراجعة يكفي للادعاء أنه أسرع أوأكثر إتاحة من Mantine في كل المكونات، أوأن استبدال المجموعة الحالية كاملًا سيحسن النتيجة دون تكلفة.

## تنفيذ التوصية

نُفذت المقارنة المنفصلة للنموذج والحوار والجدول والتاريخ، مع العربية والمظهرين واللمس وقياس حجم الإنتاج. ثبت عمل أم القرى مع حفظ ميلادي، ونجحت التدفقات المحددة في المكتبتين. يستمر Mantine أساس أطلس، وHeroUI بديل جاهز في تطبيق المقارنة. [النتائج وحدود الاختبار](COMPARISON-RESULTS.md).
